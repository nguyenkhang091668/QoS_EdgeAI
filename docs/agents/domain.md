# Domain Docs

This is a single-context repository.

## Before exploring

Read `GLOSSARY.md` at the repository root and relevant decisions in `docs/adr/`.
If either is absent, proceed silently. Create them lazily as terminology or decisions are resolved.

## Vocabulary

Use the glossary terms consistently in issues, hypotheses, tests, and refactoring proposals.
If a term is missing, check whether it is a real domain concept before adding it.

## Decisions

If a proposal conflicts with an existing ADR, identify the ADR and explain why it should be reconsidered.
